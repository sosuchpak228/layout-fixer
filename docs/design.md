# Design and release gates

## Contract

Input: one non-empty text selection in an editable window, followed by Ctrl+Alt+L. Output: replace the selection with a physical EN/RU key-map conversion, preserving letter case by default. Punctuation keys that become letters within an all-caps word inherit that word's case. `--lowercase` is an opt-in alternative. No selection, ambiguous ranges, unsupported editor, password field, foreground change, or too-long selection: do nothing.

## Why these APIs

- `RegisterHotKey`, not a global low-level keyboard hook: only one shortcut is observed, no background keystroke collection.
- UI Automation `TextPattern.GetSelection` plus `TextRange.GetText`: reads supported editors without changing shared clipboard state.
- Narrow Win32 `Edit` fallback: `EM_GETSEL` and `WM_GETTEXT` with a 500 ms timeout, restricted to the focused child control of the foreground window. Classic Notepad does not expose UIA TextPattern on this host.
- `SendInput` with `KEYEVENTF_UNICODE`: replaces the active selection without a paste operation. It is not guaranteed to work in every editor or across an elevated/secure desktop boundary.
- No implicit Ctrl+C fallback: snapshotting arbitrary clipboard formats and restoring ownership correctly across Parsec, RDP, and clipboard history is not a reliable generic transaction. The old local PowerShell tool remains an explicit compatibility option, not part of this public binary.

Rust is useful here for a self-contained native executable and deterministic Win32/COM bindings. It does not make the Windows editor-access contract universal. UIA calls to third-party providers can still stall; a later release should move selection reads to a cancellable worker with an app compatibility matrix.

## Privacy

No telemetry, network API, service, admin request, or persisted text. The process holds selected text in memory just long enough to convert and inject it. Diagnostic output contains only operation status. Crash dumps generated by Windows are outside the tool's control.

## Verified and remaining gates

- [x] Unit tests for EN/RU, punctuation, Caps Lock artifact, newlines.
- [x] Strict Clippy, formatting, locked release build.
- [x] Real standard Notepad Edit field: EN to RU and RU to EN with the alternate test hotkey, including the tray build.
- [x] Existing Ctrl+Alt+L tool left running; no startup or VPN changes.
- [ ] Manual app matrix: Chrome, Telegram, Unreal Editor, terminal, RDP/Parsec, elevated editor, clipboard-content preservation.
- [ ] Test tray menu and Explorer restart recovery on a separate release candidate.
- [ ] Public GitHub release/tag only after the app matrix is recorded; until then, use a pre-release label.

## Clipboard-manager direction

[Maccy](https://github.com/p0deje/Maccy) and [ClipKeep](https://github.com/bhargavmurki/ClipKeep) are macOS clipboard-history apps; their useful product ideas are keyboard-first search, pinning, deletion, image previews, and local-only storage. Windows already supplies basic history with Win+V. This fixer must remain clipboard-free and not silently retain copied text. A future Windows clipboard manager should be a separate, explicitly enabled product with a distinct shortcut, a pause/clear control, retention limits, sensitive-app exclusions, and no cloud sync by default. Do not couple its capture loop to the layout hotkey.
